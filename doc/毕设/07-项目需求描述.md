针对这些问题，我们让AI给我们一个技术方案：

在线Map映射表实际上是**路由表**，key = 用户uid，value=用户uid当前的websocket。

比如你想推消息给6，在map.get（6）之后就可以传消息了。

所以，这个可以简单记成一句话：“在线Map记的是【**谁在线，并且连在哪根线上**】”



知道在线Map映射表是干嘛的，接下来就是开始写代码了，因为是IM功能模块的所以我就放置在IM文件夹下。

这是AI给我的一个方案

```java
public final class OnlineWsMap {
    private static final ConcurrentHashMap<Long, Channel> ONLINE = new ConcurrentHashMap<>();

    public static void put(Long uid, Channel ch) { ONLINE.put(uid, ch); }

    public static void remove(Long uid, Channel ch) {
        ONLINE.computeIfPresent(uid, (k, old) -> old == ch ? null : old);
    }

    public static void push(Long uid, String json) {
        Channel ch = ONLINE.get(uid);
        if (ch != null && ch.isActive()) {
            ch.writeAndFlush(new TextWebSocketFrame(json));
        }
    }
}
```

## 这张在线表解决了什么问题

核心问题就一个：

> 消息写进数据库之后，怎么立刻通知正在线的那个人？

没有这张表时：

- 服务端只知道「存进 DB 了」
- 不知道 uid=6 现在对应哪条 WebSocket
- 只能让前端轮询「有没有新消息」→ 慢、费、体验差

有了 `uid → Channel`：

| 问题             | 怎么解决                            |
| :--------------- | :---------------------------------- |
| 对方在不在线？   | `get(uid) != null`                  |
| 在线的话推到哪？ | 对这个 `Channel` 做 `writeAndFlush` |
| 不在线怎么办？   | 不推，靠 DB + 以后拉历史            |

它不解决：消息存哪、会话怎么建、历史怎么查——那些是 MySQL / `ChatService` 的事。
它只解决：**实时投递**时的「找人、推送」。

```java
package org.arrinna.bilibilimockbackground.im.handler;

import cn.hutool.json.JSONObject;
import cn.hutool.json.JSONUtil;
import io.netty.channel.ChannelHandler;
import io.netty.channel.ChannelHandlerContext;
import io.netty.channel.SimpleChannelInboundHandler;
import io.netty.handler.codec.http.websocketx.TextWebSocketFrame;
import io.netty.handler.codec.http.websocketx.WebSocketServerProtocolHandler;
import lombok.extern.slf4j.Slf4j;
import org.arrinna.bilibilimockbackground.common.util.NettyUtil;
import org.arrinna.bilibilimockbackground.im.OnlineWsMap;
import org.arrinna.bilibilimockbackground.service.IChatService;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Component;

@Slf4j
@ChannelHandler.Sharable
@Component
public class WebSocketHandler extends SimpleChannelInboundHandler<TextWebSocketFrame> {

    /** Netty Handler 可能非 Spring 代理调用，用静态持有 Bean（和 teriteri 同套路） */
    private static IChatService chatService;

    @Autowired
    public void setChatService(IChatService chatService) {
        WebSocketHandler.chatService = chatService;
    }

    //这个其实是事件触发器，如果升级到websocket的协议，就获取uid，然后put到路由表中，并且继承方法
    @Override
    public void userEventTriggered(ChannelHandlerContext ctx, Object evt) throws Exception {
        if (evt instanceof WebSocketServerProtocolHandler.HandshakeComplete) {
            Long uid = NettyUtil.getAttr(ctx.channel(), NettyUtil.UID);
            OnlineWsMap.put(uid, ctx.channel());
            log.info("uid={} 上线", uid);
        }
        super.userEventTriggered(ctx, evt);
    }

    @Override
    protected void channelRead0(ChannelHandlerContext ctx, TextWebSocketFrame frame) {
        Long fromUid = NettyUtil.getAttr(ctx.channel(), NettyUtil.UID);
        String text = frame.text();
        log.info("uid={} 收到帧: {}", fromUid, text);

        JSONObject obj = JSONUtil.parseObj(text);
        String code = obj.getStr("code");
        if (!"CHAT_SEND".equals(code)) {
            ctx.writeAndFlush(new TextWebSocketFrame("{\"type\":\"ERROR\",\"msg\":\"unsupported code\"}"));
            return;
        }

        Long targetUid = obj.getLong("targetUid");
        String content = obj.getStr("content");
        Long msgId = chatService.sendText(fromUid, targetUid, content);

        // 给发送方一个 ACK
        ctx.writeAndFlush(new TextWebSocketFrame(
                "{\"type\":\"ACK\",\"msgId\":" + msgId + "}"
        ));
    }

    @Override
    public void channelInactive(ChannelHandlerContext ctx) {
        Long uid = NettyUtil.getAttr(ctx.channel(), NettyUtil.UID);
        if (uid != null) {
            OnlineWsMap.remove(uid, ctx.channel());
            log.info("uid={} 下线", uid);
        }
        ctx.fireChannelInactive();
    }
}
```

| 字段                         | 原因                                                         |
| :--------------------------- | :----------------------------------------------------------- |
| `contacts`                   | 左侧会话列表的唯一数据源；对应 `GET /contacts`，一次拉齐，点选只改「当前会话」，不用再整页重请求。 |
| `currentRoomId`              | 打开历史、已读、刷新消息都以 roomId 为准（后端 `messages` / `read` 都吃 roomId）。 |
| `currentPeerUid`             | 发消息吃的是 `targetUid`，不是 roomId；空间页「发消息」往往只有对方 uid，还可能没有 room。所以 peer 必须单独存。 |
| `messages`                   | 右侧气泡列表；跟 contacts 拆开，避免点会话时整表刷新。       |
| `loading`                    | 切会话时有网络等待，UI 需要 loading/空态，不然会闪旧消息。   |
| `myUid`（computed）          | 气泡左右：`fromUid === myUid` → 自己。从 storage 读，避免每个组件自己 `getUserInfo()`。 |
| `currentContact`（computed） | 顶栏昵称/头像/未读，直接从 contacts 里找当前行，不另存一份，避免双份状态不同步。 |
