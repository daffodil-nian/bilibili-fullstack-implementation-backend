> 更新日期：2026-09-05

## 1. 项目背景（可作论文引言素材）

面向学习与毕设演示，实现类 B 站核心能力的后端服务：**用户账号与社交、专栏内容、搜索、互动、即时通讯（规划）** 等。  
技术侧重点：Spring Boot 分层、MySQL 建模、Redis 热点计数、Elasticsearch 搜索、以及可选的 **Netty WebSocket 实时消息**。

开题定位为「参考 B 站的社区内容系统」，不追求商业级全量复刻（不做完整直播、复杂推荐算法等），以**可演示闭环 + 可扩展设计**为准。

### 3.7 即时通讯 IM 模块（规划，对齐仿 B 站「消息」）

**目标**：单聊私信实时收发；架构参考 teriteri / MallChat——**HTTP 管会话与历史，WebSocket 管实时推送**。

| 功能 | 优先级 | 阶段 | 简述 |
|---|---|---|---|
| 创建会话 / 最近会话列表 | 高 | 一期 | HTTP；表 `chat` |
| 历史消息分页 | 高 | 一期 | HTTP；表 `chat_detailed` |
| WebSocket 连接与鉴权 | 高 | 一期 | 先 HTTP 登录拿凭证，WS 首包/握手鉴权 |
| 实时发消息 | 高 | 一期 | 落库 + 推双方在线端 |
| 心跳与超时下线 | 中 | 一期 | 如 `IdleStateHandler` |
| 未读数 / 进入窗口清未读 | 中 | 二期 | Redis 窗口标记 + `msg_unread` 或会话字段 |
| 撤回 | 低 | 二期 | 时限内撤回并推双方 |
| 群聊 | 低 | 三期/展望 | 需群与成员表；**不做群内互晒公网 IP** |
| 系统通知（赞/关注） | 低 | 展望 | 可先站内信表，再 WS 推 |

**技术要点（写入设计文档即可）**：

- Netty 独立端口（如 7071）路径 `/im`，与 Spring MVC `:8080` 并存  
- Pipeline：HttpCodec → Aggregator →（可选 ChunkedWrite）→ 鉴权 → WebSocketProtocol → 业务 Handler  
- 在线结构：`Map<uid, Set<Channel>>` 支持多端  
- 消息可存 `client_ip`（服务端审计）；对用户展示 **IP 属地**，不向聊天双方广播原始 IP

### 3.8 IP 地址与属地

**获取方式**：Hutool `JakartaServletUtil.getClientIP(request)`（Spring Boot 3 使用 Jakarta 包）。  
文档：[Hutool](https://doc.hutool.cn/)；属地：[ip2region](https://github.com/lionsoul2014/ip2region/blob/master/README_zh.md)（推荐，本地库）；或第三方 IP 接口（备选）。

**何时解析**：

| 时机 | 行为 |
|---|---|
| 用户登录成功 | 解析 IP + 属地，写入用户 `ip_info`（或等价字段）并返回前端 |
| 需登录的业务请求（可节流） | 拦截器可取 IP；**属地不必每次都查库文件**，可对同一 IP 短时缓存 |
| 「刷新一次解析一次」 | 指刷新登录态/主动拉用户信息时更新属地展示；避免每个静态资源请求都解析 |
| 发送私信（IM） | 服务端记录消息或连接维度 IP，供审计；前端展示属地即可 |

**展示原则**：空间/评论/聊天对普通用户显示「IP：省份」；完整 IP 仅存服务端（管理员可查）。

**拦截器注意**：白名单（登录/注册/搜索）若提前 return，需在白名单分支内单独打日志才能在登录时看到 IP。

## 4. 用例简述（写论文可画用例图）

### 用例：用户登录
- 参与者：用户  
- 前置：已注册  
- 主成功场景：输入账号密码 → 校验 → 解析 IP/属地 → 返回用户信息与凭证  

### 用例：查看他人空间
- 参与者：登录用户  
- 主成功场景：打开 `/space/{uid}` → 请求空间接口 → 展示资料与关注粉丝数 → 可关注  
- 扩展：对方关闭粉丝列表 → 不可进入列表接口  

### 用例：发布专栏
- 参与者：登录用户  
- 主成功场景：填写标题封面摘要正文标签 → 校验 → 入库 →（已发布）写 ES → 返回文章 ID  

### 用例：查看专栏详情
- 参与者：登录用户 / 作者  
- 主成功场景：校验可见性 → Redis 点击 +1 → 组装详情 VO → 返回  
- 扩展：私密且非作者 → 拒绝  

### 用例：投币（规划）
- 参与者：登录用户  
- 主成功场景：校验余额与是否已投 → 扣钱包 → 写投币记录 → 稿件 `coin_count`+  

### 用例：每日签到（规划）
- 参与者：登录用户  
- 主成功场景：校验当日未签 → 发硬币 → 标记已签  
- 扩展：重复领取 → 拒绝  

### 用例：私信实时聊天（规划）
- 参与者：登录用户 A、B  
- 前置：均已登录；A 已创建与 B 的会话  
- 主成功场景：A 连接 WS 并鉴权 → A 发送消息 → 服务端落库 → 推送至 B（及 A）在线端 → B 界面展示  
- 扩展：B 离线 → 仅落库，B 上线后通过历史接口拉取；未读数增加

## 5. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 详情点击等高频写走 Redis；ES 承担搜索；IM 推送避免阻塞 EventLoop（业务可异步） |

| 安全 | 密码密文；HTTP 登录拦截；私密专栏鉴权；WS 必须鉴权；不向普通用户暴露他人完整 IP |
| 可维护 | Controller / Service / Dao / Mapper 分层；IM 独立 `im` 包；SQL 集中 `sql/` |
| 可演示 | 固定演示路径：注册登录 → 关注/空间 → 发专栏/详情 → 搜索 →（可选）私信 |
